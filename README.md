# www.lajollatroop506.com

The Troop 506 La Jolla website: a [Hugo](https://gohugo.io) site that
reproduces the troop's former WordPress site (minus the store), edited with
[Sveltia CMS](https://sveltiacms.app) and published to GitHub Pages.

## Editing

Go to **/admin/** on the site and sign in with a GitHub account that has write
access to this repository. Saving commits to `master`, and
[the Pages workflow](.github/workflows/pages.yml) rebuilds the site in a
minute or two.

| In the editor | Files |
|---|---|
| Blog Posts | `content/posts/<slug>.md`, shown at `/YYYY/MM/<slug>/` |
| Pages | `content/pages/<slug>.md`; the address is the `url` field |
| Home Page | `content/_index.md` (slider photos, intro, text) |
| Site Settings → Menu | `data/menu.yaml` |
| Categories | `content/categories/<slug>/_index.md` |
| Media | `uploads/`, served at `/wp-content/uploads/` like WordPress |

"Sign In with GitHub" goes through a small OAuth service: a Cloudflare Worker
deployed from [troop506/sveltia-cms-auth](https://github.com/troop506/sveltia-cms-auth)
(a fork of Sveltia's authenticator) under the Cloudflare account
eric@busboom.org (Google sign-in). Its URL is `backend.base_url` in
[static/admin/config.yml](static/admin/config.yml); see [AGENTS.md](AGENTS.md).
"Sign In Using Access Token" works without it.

New posts start as drafts. In the story editor, **Photo**, **Photo row** and
**YouTube video** insert the `image`, `photo-row` and `embed` shortcodes
(`layouts/_shortcodes/`); [static/admin/index.html](static/admin/index.html)
defines those editor blocks.

## Running locally

```bash
hugo server        # http://localhost:1313/
```

## How it matches the WordPress site

- `layouts/` is a port of the `troop506-theme` WordPress theme, printing the
  same markup, so the theme's own `style.css` (in
  `static/wp-content/themes/troop506-theme/`) and WordPress's block styles
  (`static/wp-content/css/`) style it unchanged.
- The home page slider and post grid use the Kadence Blocks markup, CSS and
  scripts from `static/wp-content/plugins/`.
- URLs are the same: posts at `/YYYY/MM/slug/`, `/category/…/`, `/tag/…/`,
  month and year archives (generated by `content/_content.gotmpl`), `/feed/`.
- Search is client-side (`/search/?s=…`, using `/search-index.json`).

## Migration

`migration/` converted the WordPress content once:

```bash
docker cp migration/export.php <wp-container>:/tmp/ && \
  docker exec -u www-data <wp-container> wp eval-file /tmp/export.php > migration/export.json
python3 migration/wp2hugo.py migration/export.json <wp-content/uploads dir>
python3 migration/extract_css.py <dir of pages saved from the WordPress site>
```

Re-running `wp2hugo.py` overwrites `content/`, `data/menu.yaml` and `uploads/`.
